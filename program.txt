----------------------------------------------------------------
РАЗДЕЛ 1. ТЕОРИЯ БИТОВОГО МНОЖЕСТВА
----------------------------------------------------------------

1) Что такое битовое множество (BitSet)?
   Это структура данных, которая хранит подмножество целых чисел
   от 0 до N-1 с помощью отдельных битов. Если i-й бит равен 1,
   значит число i входит в множество; если 0 — не входит.
   В проекте N = 100, то есть хранятся числа от 0 до 99.

2) Как BitSet хранит данные внутри?
   В моём классе объявлено поле:
       std::bitset<100> bits;
   Это стандартный контейнер STL, который занимает 100 бит
   (около 13 байт), а не 100 int (400 байт) и не 100 указателей,
   как std::set. Каждый элемент — ровно один бит.

3) Чем BitSet лучше обычного массива bool? Чем лучше std::set?
   - Против массива bool/vector<bool>: битовые операции над
     множествами выполняются одной-двумя командами процессора
     на весь массив (а не циклом по элементам).
   - Против std::set: в разы меньше памяти (бит вместо узла
     дерева) и быстрее объединение/пересечение.
   Ограничение: работает только для компактного диапазона
   неотрицательных целых чисел, известного заранее (0..99).

4) Какое главное ограничение вашей реализации?
   Диапазон фиксирован: 0..99 (MAX_SIZE = 100). Отрицательные
   числа и числа >= 100 не поддерживаются — методы add/remove/
   contains просто игнорируют такое значение (проверка
   element >= 0 && element < MAX_SIZE).

5) Что будет, если подать отрицательное число или 250?
   Ничего плохого: проверка в add/remove/contains отсекает
   такие значения, бит не меняется. В GUI ещё раньше срабатывает
   проверка ввода — выводится предупреждение QMessageBox
   «Введите число от 0 до 99».


----------------------------------------------------------------
РАЗДЕЛ 2. КОД КЛАССА BitSet (bitset.h / bitset.cpp)
----------------------------------------------------------------

6) Почему MAX_SIZE — статическая константа?
   Потому что размер множества одинаков для всех объектов класса,
   а для std::bitset<N> N обязан быть известен на этапе компиляции.
   static const size_t MAX_SIZE = 100; объявляется один раз на класс.

7) Какие методы получили квалификатор const и почему?
   const у contains, unite, intersect, difference, size, toString,
   isEmpty, getElementsList. Эти методы не изменяют объект,
   поэтому их можно вызывать и у константных объектов, и они
   безопасны для использования в const-контексте. Это хороший
   стиль C++.

8) Почему unite/intersect/difference возвращают BitSet по значению,
   а не меняют this?
   Так они реализуют математические операции над множествами
   без побочных эффектов: A.unite(B) не меняет ни A, ни B,
   а даёт новое множество. Это позволяет свободно комбинировать
   результаты и возвращать их прямо в GUI.

9) Какие битовые операции используются в реализации?
   - unite:       result.bits = bits | other.bits;     (побитовое ИЛИ)
   - intersect:   result.bits = bits & other.bits;     (побитовое И)
   - difference:  result.bits = bits & ~other.bits;    (И с инверсией)
   difference = элементы A, которых нет в B. Именно инверсия (~)
   отличает разность от пересечения.

10) Как работает size()?
    Через встроенный метод std::bitset::count(), который считает
    количество единичных битов. Сложность O(N), но на практике
    процессор делает это очень быстро специальными командами
    (popcount).

11) Как работает isEmpty()?
    Возвращает bits.count() == 0, то есть «единичных битов нет».

12) Как формируется строка для вывода в интерфейс?
    Метод toString() идёт по битам от 0 до 99, и для каждого
    единичного бита добавляет его номер через QString::number(i)
    в строку вида "{ 1, 3, 5 }". getElementsList() делает то же,
    но каждый элемент с новой строки (для многострочного вывода).

13) Что делает конструктор BitSet()?
    Инициализирует bits(0), то есть все 100 бит равны нулю —
    множество пустое. Это же используется при очистке кнопкой
    «Очистить A»: setA = BitSet(); — присваивание свежего
    пустого объекта.


----------------------------------------------------------------
РАЗДЕЛ 3. GUI И Qt (mainwindow.h / mainwindow.cpp)
----------------------------------------------------------------

14) Что такое сигналы и слоты в Qt? Как они используются у вас?
    Сигнал — событие (например, clicked() кнопки), слот —
    метод-обработчик. Соединение делается через connect:
        connect(btnAdd, SIGNAL(clicked()), this, SLOT(onAddClicked()));
    Здесь используется старый синтаксис SIGNAL/SLOT (строковый) —
    он корректен и совместим с Qt 4.11.

15) Зачем Q_OBJECT в классе MainWindow?
    Это макрос Qt, который включает поддержку метаобъектной
    системы: сигналы/слоты, свойства, tr() для переводов.
    Без него не сработает connect() и не соберётся moc.

16) Зачем в .pro файле QT += gui и QT += widgets?
    QT += gui — модуль базовой графики (QString, QWidget, QApplication).
    QT += widgets — классы виджетов (QPushButton, QTextEdit и др.).
    Строка greaterThan(QT_MAJOR_VERSION, 4): QT += widgets нужна
    ради совместимости: в Qt 4 модуля widgets не было (он был
    частью gui), а в Qt 5 он вынесен отдельно.

17) Как устроен интерфейс (layout)?
    Главное окно: QMainWindow, центральный виджет — QWidget.
    Внутри — QVBoxLayout с группами QGroupBox:
      - панель ввода (QLineEdit для числа + QComboBox A/B + кнопки);
      - два блока отображения множеств A и B (QTextEdit, только чтение);
      - кнопки операций над множествами;
      - лог операций (QTextEdit).
    Layout-менеджеры сами растягивают виджеты при изменении размера окна.

18) Как реализована проверка ввода?
    В слотах onAddClicked/onRemoveClicked:
        bool ok;
        int elem = elementInput->text().toInt(&ok);
        if (!ok || elem < 0 || elem >= 100) { ... warn ... }
    toInt(&ok) возвращает ok = false, если в строке не число.
    Дальше отсекается выход за диапазон 0..99.

19) Почему множества A и B — поля класса, а не локальные переменные?
    Поля setA и setB живут всё время работы окна, поэтому все
    обработчики кнопок работают с одними и теми же множествами.
    Если бы они были локальными, данные терялись бы после
    нажатия кнопки.

20) Что выводит вывод операции пользователю?
    Результат кратко пишется в лог (appendLog) и показывается
    в QMessageBox с самим множеством и его размером. Так
    пользователь сразу видит и историю, и результат операции.


----------------------------------------------------------------
РАЗДЕЛ 4. СБОРКА И ЗАПУСК
----------------------------------------------------------------

21) Как собрать проект в Qt Creator?
    Открыть bitset.pro, выбрать Kit (Desktop Qt), нажать
    «Собрать» (Ctrl+B), затем «Запустить» (Ctrl+R). Qt Creator
    сам вызовет qmake и make.

22) Как собрать из терминала?
        qmake bitset.pro
        make
        ./bitset
    Есть и скрипт build.sh, и CMakeLists.txt как альтернатива.
    Если после правки .pro появляются странные ошибки — сделать
    «Очистить» (make clean) и собрать заново.

23) Была ошибка «No rule to make target 'mainwindow.ui'». Почему?
    В .pro была строка FORMS += mainwindow.ui, но самого .ui-файла
    не было (интерфейс строится кодом, а не в Designer). Строку
    из .pro убрали — сборка заработала.

24) Почему на Linux нет проблем с кириллицей, а в Windows бывают?
    В исходниках строки в UTF-8. На Linux/мингв обычно всё
    нормально. На старых MSVC иногда нужно добавлять
    /utf-8 или использовать QString::fromUtf8 — но это уже
    вне рамок задания.


----------------------------------------------------------------
РАЗДЕЛ 5. ВОПРОСЫ «С ПОДВОХОМ»
----------------------------------------------------------------

25) Приведите элементы множества {2, 3} в «ручной» двоичный вид.
    Бит 0 — младший. {2,3} = только биты 2 и 3 равны 1:
        0b00001100  (биты 2 и 3 установлены)
    Если добавить 0, получится 0b00001101.

26) Чему равно пересечение {1,3,5} и {3,4,5}?
    Общие элементы только 3 и 5 -> {3, 5}.
    На битах: 0b101010 & 0b111000 = 0b101000 (биты 3 и 5).

27) А разность {1,3,5} \ {3,4,5}?
    Элементы первого множества, которых нет во втором -> {1}.
    На битах: 0b101010 & ~0b111000 = 0b000010 (бит 1).

28) Что произойдёт, если нажать «Очистить A» и затем «Пусто?»?
    Множество A станет пустым (setA = BitSet()), и проверка
    пустоты покажет «Пусто» для A. Это правильное поведение:
    isEmpty() возвращает true.

29) Почему std::bitset<100>, а не std::vector<bool>?
    Чтобы размер был фиксирован на этапе компиляции и операции
    над всем множеством выполнялись одной битовой командой.
    vector<bool> — это «странный» контейнер-прокси, и с ним
    битовые операции над всем вектором напрямую не делаются.
    У std::bitset есть готовые операторы |, &, ~, count().

30) Что бы вы изменили, если диапазон был бы 0..1000000?
    Тогда фиксированный bitset неудобен (1 Мбит = 125 КБ —
    всё ещё нормально, но гибче — динамика). Использовали бы
    динамическое битовое поле (vector<uint64_t>) с вычислением
    номера слова и маски, либо разреженную структуру (std::set)
    для очень разреженных множеств.
    Для сравнения: при 10000000 элементов уже std::set может быть
    выгоднее по памяти, если заполнено малое количество.


================================================================
  КОРОТКО: ЧТО ГОВОРИТЬ НА ЗАЩИТЕ (1-2 минуты)
================================================================

  1. Класс BitSet хранит std::bitset<100>; элемент i — это
     i-й бит. Память — 100 бит, а не 100 int.
  2. add/remove/contains ставят, снимают и читают бит,
     проверяя диапазон 0..99.
  3. Объединение, пересечение и разность — это битовые
     операции |, &, & ~, поэтому они выполняются очень быстро
     и над всеми элементами сразу.
  4. GUI на Qt 4.11: QMainWindow + layout, сигналы/слоты через
     connect(), проверка ввода через toInt(&ok), результат
     выводится в лог и в QMessageBox.
  5. Сборка: qmake bitset.pro && make && ./bitset
     (проект собран на Linux, Qt 4.11).
